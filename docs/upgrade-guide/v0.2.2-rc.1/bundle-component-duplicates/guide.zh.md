# 插件组合包中的重复组件 ID

[English](guide.md) | 中文

## 变更

此前，插件管理器允许已选择的主组合包与独立组合包插入相同的组件 ID。现在通过服务、网页或管理工具启用其他组合包时，会在保存冲突选择之前返回 `duplicate-entry`，即使已有组件处于关闭状态。同一模块使用不同 ID，以及普通配置覆盖，仍然受支持。已有选择不会被静默删除。

未选择的组合包若全部组件已由一个已选择组合包提供，`listBundles()` 可返回 `providedBy`。网页会标明提供方，并展示现有组件的控制项，而不是提供第二次包激活入口。`enabled` 仍表示是否选择了独立组合包；该值为 false 不代表包所命名的所有组件均未激活。

## 迁移

1. 检查受影响 profile 的 `package.json` 中的 `dsh.profile.bundles`。若主组合包和独立组合包提供了相同的组件 ID，保留主组合包，并取消冗余独立组合包的选择。若主组合包仍需要它，不要卸载其依赖。
2. 在 profile 的 `cordis.patch.yml` 中保留组件激活设置，每个 ID 只对应一个可唯一寻址的条目。不要通过新增组合包层激活主组合包已经提供的组件。
3. 在网页「插件」中打开标记为「已由其他插件包提供」的包，并使用组件开关。核实运行时条目已启用且 active，同时独立包仍处于未选择状态。
4. 穷举处理 `ManagementError['code']` 的客户端必须处理 `duplicate-entry`。`listBundles()` 的客户端可使用可选字段 `providedBy` 区分组件提供关系与包选择。
