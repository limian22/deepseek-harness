# 管理页面与会话读取性能实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task.

[English](2026-11-10-management-session-read-perf.md) | 中文

**目标：** 减少插件管理元数据和会话列表文件系统的重复读取，同时保持新鲜度和授权规则。

**架构：** 插件管理继续由现有 Remote 和状态仓库负责；可用性检查不再依赖完整清单，并在单次操作内去重元数据。JSONL 持久化保留规范世代发现，仅复用已检查当前文件身份的观测，不使用基于时间的新鲜度或全局缓存。

**技术栈：** TypeScript、Cordis、Typert、React 状态仓库、Node 文件系统接口和 Vitest。

---

## 范围与约束

本文是两条已测读取路径的执行参考，不重新设计应用启动。实现以当前检出目录为目标，不新增检出目录或复制仓库。测试使用单工作进程串行执行。产品配置、运行产物、服务进程和浏览器调试保持不变。

实现前的本机已认证采样：会话列表 843 行、1,040,129 字节，耗时 2.42 秒；后续调用超过六秒限制。插件清单耗时 1.37 秒，插件包耗时 2.33 秒，插件配置耗时 1.57 秒。这些是单次后端采样，不是浏览器延迟分位数或冷启动测量。

## 任务 1：插件管理

**文件：** `packages/client/ui-plugin-manager/src/client/manager-store.ts`、对应状态仓库测试、`packages/host/plugin-inventory/src/index.ts`，以及仅在需要时修改 `packages/boot/app-boot` 或 `packages/boot/plugin-manager` 中归属明确的元数据辅助函数。

1. 为不必要的完整清单前置查询和重复元数据读取添加失败回归。保留受管理和不受管理场景、错误、刷新世代和释放行为。
2. 仅执行相关测试：`node node_modules/vitest/vitest.mjs run <selected-spec> --maxWorkers=1`；修改实现前记录预期失败断言。
3. 尽可能复用轻量的现有可用性结果；如果需要新增 Remote，则同时更新其声明和调用者。在单次操作内复用元数据，不引入长期 TTL 缓存。
4. 重跑所选测试及既有可用性和访问控制测试。断言消除的调用次数与相同返回数据，不依赖墙钟阈值。
5. 更新受影响的 README 双语文件及配对记录。不激活或重建正在运行的宿主。

## 任务 2：会话持久化列举

**文件：** `packages/session/session-persistence-jsonl/src/index.ts`、包内列表测试和 README 双语文件。

1. 检查实际目录、世代、头部、身份和版本读取。除非存在等价的新鲜观测，否则不得删除最终身份检查。
2. 使用临时合成会话添加真实文件系统失败回归，验证重复列举工作。在受影响时覆盖外部追加或替换、新增或删除会话、世代选择、历史转换、取消和并发列举。
3. 任务 1 释放测试时隙后，单工作进程运行所选回归并记录 RED。
4. 保留目录发现与当前文件身份检查。仅在失效规则明确、实例拥有、保留量有界，且不缓存失败或未完成读取时，复用未变化的头部工作。
5. 串行执行所选回归及相关既有世代或迁移夹具。比较文件系统调用次数和返回快照；性能测量与正确性断言分开。
6. 更新 README 语义和双语配对记录，不修改持久化格式或既有会话世代。

## 任务 3：集成与证据

1. 审查完整范围内的差异，并检查所有变化的产品调用者。
2. 按需运行局部类型或生成检查，不做整仓构建。若产物前置条件阻止检查，则明确说明缺失的验证，而不是报告成功。
3. 两项实现结束后，串行执行局部空白、文档配对和 lint 检查。
4. 报告实测工作量减少、已执行的通过或失败数量、剩余延迟部分，以及源码变更和运行激活的区别。未部署并测量对应产物，不宣称在线接口获得新速度。

## 验收

插件管理不再仅为判断可用性而依赖完整清单。重复元数据工作减少，且不产生过期的插件包数据。会话列表在外部变更和规范世代选择后仍保持新鲜，未变化的文件避免重复读取工作。认证、取消、释放和序列化结果保持既有行为。本计划不重启或停止任何服务。
