# 增量会话搜索实施计划

[English](2026-11-11-session-search-incremental.md) | 中文

> **执行方式：** REQUIRED SUB-SKILL: 本次会话内直接执行（TDD）——由子代理实施，并设只读自动化审查检查点；不逐批追加人工批准。部署仍需单独授权。

**目标：** 不等待全语料读取即可返回已授权的索引历史，同时在后台持久保存可续建进度，并报告覆盖缺口。

**架构：** 保留面向需要搜索时精确对账调用方的同步模式。为 SQLite 提供方增加后台模式，只持久保存已校验的逐会话世代，并维持实时优先。通过仓库支持的工作线程卸载高 CPU 准备与索引发布；任意持久化后端仍通过现有读取句柄访问。

**技术栈：** TypeScript、Cordis effect 与服务、Node 工作线程、SQLite FTS5/WAL、Vitest，以及现有 Loader 和录制会话测试支持。

---

## 全局约束

- 用户接受正常负载下约五秒的历史同步延迟。这是目标，不是首次索引或恢复时的保证。
- 实施期间绝不修改活动 profile、切换运行入口、启动替代服务、停止服务或重启服务。
- 只在隔离分支工作。原始会话产物不变；测试使用私有临时根目录与合成消息。
- 搜索排序、过滤语义、工作区权限、步骤截止点、游标与快照行为、实时优先均保持不变。
- 区分空结果与覆盖不全。只报告请求范围内的进度，不暴露未授权标题、标识、计数或路径。
- 每个后台操作都有实例所有者、取消、失败隔离及可等待的清理。取消查询不取消共享同步。
- 检查来源修订后逐会话原子发布。中断不丢失已提交进度。只在成功完整列举后删除。已知变化或无效的世代在替代内容提交前隐藏。
- 工作线程消息跨线程时必须校验。不引入第二个原始会话解析器，也不绕过当前格式目录校验。

## 测量记录

用户操作：首次与重复的模型历史搜索，包括尚未索引的语料与并发更新。负载：确定性合成语料、多种会话大小，以及证明查询独立性的阻塞读取。入口：真实 SQLite 服务与模型工具；使用工作线程时验证 Loader 和构建产物。计时分别记录构造、同步、查询及工具标题与权限处理。排除模型生成与网络耗时。记录基线、候选样本、实测内存、运行时和负载维度。负对照：阻塞读取查询测试必须在原前台路径失败。不能把解压后丢弃数据的耗时当成端到端搜索延迟。

## 任务 1：建立回归与共享覆盖 API

**文件：** `packages/session-query/session-query/src/types.ts`、`packages/session-query/session-query/src/index.ts`、对应服务测试及本计划。

1. 修改前运行现有 SQLite 与工具测试。基线为两个文件共 177 个测试通过；在进度记录中保存命令与结果。
2. 新增 `SessionSearchCoverage`，并在搜索分页增加可选 `coverage`。字段为 `state`（`initializing`、`syncing`、`ready`、`degraded`）、可选 `checkedAt`，以及可选且限定授权范围的 `indexedSessions`、`pendingSessions`、`failedSessions`。不提供 coverage 时保持现有精确提供方语义。对象中不输出来源失败原文或全局计数。
3. 使用可控 promise 编写行为测试，断言后台查询先于阻塞的持久读取返回；实现前先观察失败。不以墙钟时序保证正确性。
4. 验证类型消费方，并在服务定义旁记录新鲜度语义。

## 任务 2：支持可续建发布的后台提供方

**文件：** `packages/session-query/session-query-sqlite/src/`、其测试与 README 双语文档。

1. 先测试：首次读取或重试阻塞不阻塞搜索；后续读取失败不隐藏已经提交的会话；已知变化的数据隐藏；扫描中断不删除；查询取消不取消共享任务；卸载等待或取消自有任务；范围内覆盖不泄露其他工作区。
2. 新增经过校验的 `syncMode: 'on-search' | 'background'`（默认 `on-search`）、`syncIntervalMs`（默认 5000）与 `syncReadConcurrency`（默认 2）。生命周期通过 Cordis effect 管理。保留现有 on-search 测试。
3. 在查询串行队列之外同步，只把有界原子发布放入队列。合并请求并在活动期间定期对账。提交前检查持久化来源身份与修订。保留已提交世代，只重试待处理或变化来源。
4. 通过请求的全部会话谓词限定 coverage，事件搜索限定为目标会话。已知待处理目标不能因尚未索引而误报 SESSION_NOT_FOUND。
5. 运行新增聚焦测试，再运行现有提供方测试。

## 任务 3：线程外准备与磁盘索引组合

**文件：** 由工作线程集成调查确定的线程与持久化文件；`packages/experimental/session-search/cordis.patch.yml`，以及仅在必要时修改的启动器上下文与测试。

1. 复用现有独立格式目录与工作线程启动支持。选择辅助实现前读取其确切接口，不让通用查询服务导入 JSONL 实现来猜测路径。
2. 实现前编写构建入口测试，覆盖来源校验、消息校验、来源变化取消与工作线程清理。
3. 索引路径跨重载稳定，并按 profile、来源根目录与逻辑服务所有者隔离。拒绝不受支持或缺少授权依据的磁盘路径，不静默允许运行中进程共享可写索引。
4. 在临时持久根目录验证冷暖重新打开，并断言来源产物逐字节不变。

## 任务 4：模型可见覆盖与安全标题补充

**文件：** `packages/experimental/tool-session-query/src/operations.ts`、`src/presentation.ts`、测试与 README 双语文档；输出变化时更新录制会话归属目录。

1. 测试部分空页不渲染为普通完整无匹配结果。覆盖 ready、部分命中、跨页聚合与省略未授权进度。
2. 收集多页时保留覆盖状态。输出精简稳定的新鲜度文本，不包含后端内部信息或来源路径。
3. 不因标题补充增加无关语料读取。输出标题或摘录之前保持权限检查。
4. 运行工具与 SQLite 集成测试，再运行对应的无密钥录制场景。

## 任务 5：审查与验收

1. 由其他审查代理检查规格、错误、生命周期所有权、安全和资源边界。修复实质问题并重跑相关检查。
2. 运行聚焦单元、Loader、工作线程与快照测试；用相同入口测量合成语料修改前后的搜索工作。
3. 最后代码修改后运行相关制品构建，再执行构建检查。运行聚焦 lint 与文档检查，报告确切退出码及未覆盖项。
4. 审查完整最终差异，交付分支、测试、性能证据与部署回滚说明，不声称当前在线 GUI 已加载新代码。
