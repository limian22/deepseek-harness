# 子代理模型策略实施计划

[English](2026-11-08-subagent-model-policy.md) | 中文

> **执行提示：** 使用 executing-plans 技能逐项实施。

**目标：** 用户选择的子级模型列表同时约束隐式与显式委派路由。

**架构：** 保留持久化的 Session 策略和现有设置生效范围。省略路由时，在策略内确定性解析：保留列表内生效的配置路由，其次使用列表内的父路由，否则选择首个授权路由。提供方报错后不得静默回退到列表外模型。未配置或关闭策略的会话保留原有行为。用户在本会话明确批准“限定使用勾选模型”。

**技术栈：** TypeScript、Cordis、Vitest、pnpm。

## 全局约束

- 不改动已有的无关工作区修改。
- 当前执行轮次不重启生产服务，不修改在线 profile 插件。
- 空的生效策略拒绝委派；显式指定无效路由仍拒绝。
- 更换路由时清除继承的推理强度，保留其他 Agent 选项。
- 区分测试结果、构建产物、运行时加载与真实提供方响应的验收状态。
- 固定模型的外部 CLI 代理需要单独评估，不能意外改换其路由。

## 任务 1：省略路由时遵守策略

文件：`packages/subagent/tool-subagent/src/model-selection.ts`、`src/index.ts`、`tests/model-selection.spec.ts` 及相关包文档和测试。

1. 将允许列表外默认值的旧测试改为必须使用授权路由。覆盖 GPT 父级只授权 Flash、多模型确定性顺序、授权默认值／父级、部分配置路由、非 LLM 选项保留、强度清除、空策略、显式拒绝、关闭或无策略兼容性以及 fork 复用。
2. 执行 `pnpm exec vitest run packages/subagent/tool-subagent/tests/model-selection.spec.ts`，在实现之前记录失败断言。
3. 在共享解析器中实现策略感知解析。创建子级前预检最终路由；不能把提供方默认值意外带入其他路由。
4. 执行 `pnpm exec vitest run packages/subagent/tool-subagent`，检查所有失败后再继续。

## 任务 2：入口审计及一致性

审计确认工作流直接调用 `startActivation`，而普通工具使用工具本地解析器。把策略、投影及共享纯路由函数迁入 `packages/subagent/subagent/src/model-selection.ts`，通过原工具本地文件重新导出以保持兼容，并在精确父级授权之后的共享服务入口实施约束。显式列表外路由拒绝；省略选择时解析授权路由；无法遵守已记录策略的固定后端拒绝。添加核心服务和工作流宿主回归测试，先红后绿，再运行两个包的测试。声明归属变化时重新生成当前持久化目录，不改冻结的发布 schema。不重启服务，不修改在线 profile。

## 任务 3：审查、界面说明与验收

1. 更新设置说明，明确省略路由也受限制，并记录确定性默认顺序。
2. 独立审查集成后的差异，覆盖路由预检与策略绕过。
3. 执行相关委派、工作流和设置测试，并在可行时做定向类型检查。
4. 使用仓库支持的命令构建受影响产物，避免与其他构建竞争或覆盖无关修改。
5. 报告运行进程是否加载修复；需要重启后端时，在维护窗口执行受控激活，再实测省略路由的委派。
