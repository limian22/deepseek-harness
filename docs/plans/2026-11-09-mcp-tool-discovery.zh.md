# MCP 工具发现实施计划

[English](2026-11-09-mcp-tool-discovery.md) | 中文

> **供 Claude 使用：** 必须使用 executing-plans 技能逐项实施本计划。

**目标：** 提供 MCP 工具检索和按需调用，不再将每个远程工具的参数定义放入每轮模型请求，同时保留现有执行策略与持久化审计记录。

**架构：** 保留原始 MCP 工具注册及其作用域限制、步骤准入。增加显式启用的发现模式，只将精简发现与调用入口提供给模型；选中的原始工具通过共享工具流水线执行。复用现有嵌套调用记录语义，不改变持久化事件字段或智能体循环。

**技术栈：** TypeScript、Cordis、Schemastery、MCP SDK、Vitest，以及现有原生与 PTC 工具执行器。

---

## 范围与验收

- 仅在 `mcp-tool-discovery` 分支的独立工作树内工作。不修改运行中的 profile、配置、服务、启动器、隧道，也不触碰原检出目录中的其他改动。
- 默认保留直接暴露模式。通过 MCP client 和 MCP manager 对各服务显式配置发现模式。
- 不依赖模型服务商支持延迟工具。即使服务商只接受立即提供的完整定义，默认请求也保持精简。
- 原始公开工具名称仍用于校验、guard、审批、超时、取消、执行后策略，以及持久化嵌套调用记录。
- 发现必须读取调用方作用域内、当前步骤准入的注册，禁止通过全局缓存绕过限制或读取旧连接代次。
- 搜索必须确定、有界，支持分页与精确查询，并显式报告省略。只在请求时返回完整参数定义。
- 转发执行后策略确认的权威内容。策略阻断或替换结果后，禁止返回原始成功值。
- 不改变资源与服务端指令；分别报告这些仍存在的上下文成本。

## 测量卡

| 字段 | 决定 |
|---|---|
| 用户操作 | 准备 MCP 服务的模型工具声明、发现一个工具并调用 |
| 负载 | 固定合成目录，覆盖小目录及具有长说明、嵌套参数的 250 工具目录 |
| 入口 | 真实 MCP 注册和系统提示组装，采用原生执行并覆盖 PTC 回归 |
| 指标 | 序列化工具声明的 UTF-8 字节数与工具数；只有存在对应模型的准确 tokenizer 时才报告 token 数 |
| 排除项 | 网络与模型延迟、真实外部服务行为、用户私有工具元数据、服务端指令和资源 |
| 判据 | 远程目录增长时发现模式的默认声明保持恒定；大目录声明显著缩小；直接模式作为负对照 |
| 行为 | 原始名称策略拒绝、输入失败、成功结果、取消、重新同步、移除与持久化嵌套身份 |

### 任务 1：工具展示与执行基础

**文件：**
- 必要时修改：`packages/core/tools/src/contracts.ts`、`packages/core/tools/src/index.ts`、`packages/core/tools/src/pipeline.ts`。
- 必要时修改：`packages/core/tool-executor-native/src/index.ts`、`packages/core/tool-executor-ptc/src/index.ts`、`packages/core/tool-executor-ptc/src/types.ts`。
- 测试：`packages/core/tools/tests/tools.spec.ts` 及相关执行器测试。

1. 在选择扩展方式之前阅读工具注册、受控调用流水线、原生声明、PTC 绑定和嵌套记录实现。
2. 编写失败测试：已注册工具不出现在模型声明中，但仍可在原始作用域内通过受控嵌套调用执行。
3. 运行 `pnpm exec vitest run packages/core/tools/tests/tools.spec.ts`，确认因缺少该能力而失败。
4. 实现 MCP 消费者所需的最小通用展示区分。访问限制与展示元数据分离；不得将省略参数定义当作安全控制。
5. 模型声明和执行器指导文字均不包含隐藏定义，而自省和执行查询仍保留已准入的原始工具。
6. 运行聚焦测试，覆盖作用域限制、步骤失效、同名遮蔽和原生/PTC 行为。记录准确命令与结果。

### 任务 2：MCP 发现与调用

**文件：**
- 新增：`packages/mcp/mcp-client/src/discovery.ts`。
- 修改：`packages/mcp/mcp-client/src/index.ts`、`packages/mcp/mcp-client/src/tools.ts`，以及必要的连接与代次参数转发。
- 新增：`packages/mcp/mcp-client/tests/discovery.spec.ts`。
- 修改：`packages/mcp/mcp-manager/src/index.ts` 及对应 manager 测试。

1. 编写发现模式失败测试：原始注册仍存在，但只有精简发现与调用声明进入模型请求。
2. 编写确定性匹配、空查询分页、精确查询、非 ASCII 文字、完整结果字节限制和单个超大定义的失败测试。
3. 运行 `pnpm exec vitest run packages/mcp/mcp-client/tests/discovery.spec.ts`，观察因能力缺失而失败。
4. 为暴露模式与结果预算增加有校验、具有显式默认值的配置。贯通两种传输、连接代次及 manager 创建的 client。
5. 发现只读取当前调用方可见的原始定义；拒绝旧注册或其他插件的同名遮蔽，不得误路由到另一服务。
6. 通过 `ToolExecutionPipeline` 以原始名称执行，传递智能体、步骤准入、父 token、根调用身份与取消信号。
7. 外层调用返回前记录嵌套开始与结束。保留原始参数、错误状态、权威内容和展示元数据；转发延迟上下文及成功结束回合标志。
8. 测试原始名称策略拒绝且无远程副作用、原始参数无效、原始工具不可用或受限、取消、超时、重新同步、卸载与执行后策略替换。
9. 运行 MCP client、manager 和相关核心执行器测试。已存在依赖安装或构建任务时不得重复启动。

### 任务 3：真实组合、记录与测量

**文件：**
- 在 `packages/mcp/mcp-client/tests/fixtures/` 和 `packages/mcp/mcp-client/tests/` 增加包内 Loader 夹具及非单元组合测试。
- 若现有支持允许，使用既有夹具注册机制在 `snapshots/` 增加无密钥、模型可见的记录会话用例；缺少的测试框架支持纳入本次改动。
- 在 `packages/mcp/mcp-client/tests/discovery.spec.ts` 或独立聚焦 spec 中增加包内测量断言。

1. 使用受控本地夹具服务，通过真实 Loader 启动生产 MCP 插件，不读取用户私有配置。
2. 断言模型工具声明、发现输出、原始调用成功、拒绝，以及包含原始名称的持久化嵌套记录。
3. 在无密钥快照中固定稳定的模型可见文字及动态省略行为。
4. 使用相同固定目录比较直接模式与发现模式的声明；报告准确字节数、数量和比例，不编造 token 数。
5. 运行对应组合与快照命令，将平台或依赖限制与功能结果分别报告。

### 任务 4：文档、评审与验证

**文件：**
- 更新 MCP client、manager 及受影响核心工具约定的中英文 README。
- 公开类型变化时更新 `docs/subsystems/mcp.md`、`docs/subsystems/mcp.zh.md` 及工具子系统参考。
- 使用现有生成器更新相关配置、工具和 API 目录，不手改生成区域。

1. 在所属包内说明显式配置、发现工作流、权限、成本、失败行为、生命周期与限制。
2. 使用仓库配对工具重新记录已编辑的双语文档。
3. 进行独立代码评审，重点检查权限绕过、作用域泄露、旧连接代次、预算限制、结果替换、取消和嵌套记录。
4. 对确凿问题补充回归测试并修复。
5. 运行聚焦 Vitest、改动源码的 lint、相关文档检查及 `git diff --check`。
6. 运行 `pnpm run build:artifacts`，再在最新产物之后运行 `pnpm run build:check`，记录退出状态。无法完成时说明具体阻碍，不得宣称已经验证。
7. 检查最终差异。报告声明缩减实测值、准确检查命令、尚未验证的外部服务行为、分支与工作树位置，并明确线上尚未启用。

## 分工

实现代理负责生产源码及包内测试。主代理负责本计划、文档、目录集成和最终验证。独立评审代理阅读最终差异并报告可操作问题。并行写入范围必须互不重叠。
